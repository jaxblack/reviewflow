# 演示场景

执行以下命令可写入固定的演示数据：

```bash
npm run build
npm run seed:demo
```

种子只使用 `demo-*` ID，不会删除或修改手工创建的内容。重复执行不会生成重复记录。当前共 48 条，既保留可逐项讲解的核心案例，也提供接近真实审核队列的数据密度。

| --- | ---: |

除下方 9 条核心案例外，另有 39 条涵盖账户、支付、隐私、社区、营销、客服、配送和通知等业务语境的内容。可使用工作台的标题搜索、状态筛选和风险筛选快速定位。

## 核心案例

| 内容标题 | 风险 | 当前状态 | 规则 |
| --- | --- | --- | --- |
| 周末运营排期草稿 | LOW | DRAFT | 草稿可以编辑和提交 |
| 帮助中心文案更新 | LOW | IN_REVIEW | LOW 等待一位审核人决定 |
| 隐私政策调整 | HIGH | IN_REVIEW | Bob 已通过，当前进度 1/2 |
| FAQ 拼写修订 | LOW | APPROVED | 一位审核人通过后结束 |
| 账户注销流程更新 | HIGH | APPROVED | Bob、Chen 两位不同审核人通过 |
| 活动规则存在歧义 | HIGH | REJECTED | Bob 先通过，Chen 拒绝后结束，两个决定都保留 |
| 图片授权说明不足 | LOW | REJECTED | 拒绝理由非空，作者可以修改并重新提交 |
| 用户通知模板（修订版） | HIGH | APPROVED | 第一轮拒绝，修改后第二轮重新计票并通过 |
| 紧急服务公告 | LOW | APPROVED | 并发终态只保留先成功的一条有效决定 |

## 负向规则

以下规则不会通过伪造非法记录展示，而由 API 和自动化测试验证：

- 作者不能审核自己的内容。
- 只有 ADMIN 角色不能执行审核。
- 空白拒绝理由不会生成审核记录。
- 同一审核人在同一轮不能产生两条决定。
- 相同幂等键重试不会产生重复记录。
- 终态通过与拒绝并发时，失败请求不会留下决定。

## 演示顺序

1. 使用 Alice 查看全部内容，编辑“图片授权说明不足”。
2. 使用 Bob 审核“帮助中心文案更新”。
3. 使用 Chen 查看“隐私政策调整”的 1/2 进度并完成第二票。
4. 使用 Diana 查看全部内容，确认 ADMIN 只能查看。
5. 打开“用户通知模板（修订版）”，比较两轮不同快照和审核历史。
