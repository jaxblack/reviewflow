03 / Guided acceptance

七步复现完整审核闭环

准备：打开工作台左侧“新手引导”，或按下表操作。UI 引导提供 6 个角色/队列导航步骤，不会自动执行写操作；下表额外拆出 R2 的 Bob + Chen 双人通过，因此是 7 个完整业务步骤。请求默认按最近更新时间倒序排列，新建或刚处理的内容会出现在对应队列首位，无需填写或搜索固定示例标题。
步骤操作人具体操作预期结果
1Alice · 提交人点击“新建内容”，填写唯一标题和正文，风险选择 HIGH，然后点击“暂存草稿”。状态保持 DRAFT；可以继续编辑，且尚未创建 revision 和审核轮次。
2Alice · 提交人完整验收在草稿详情点击“提交审核”；日常操作也可在创建表单点击“直接提交审核”。状态进入 IN_REVIEW；详情显示 R1、0/2 和不可变提交快照。
3Bob · 审核人切换 Bob，进入“待我审核”，打开首条最新请求，填写意见并点击“通过”。内容仍为 IN_REVIEW；R1 进度变为 1/2，Bob 决定进入历史。
4Chen · 审核人切换 Chen，打开首条最新请求，填写非空拒绝理由并点击“拒绝”。R1 和内容同时 REJECTED；Bob 的通过和 Chen 的拒绝都保留。
5Alice · 提交人切换 Alice，在“我的提交”打开首条最新的已拒绝请求，编辑正文后保存并点击“重新提交”。创建 R2；进度从 0/2 开始，R1 的票不进入 R2。
6Bob + ChenBob 和 Chen 依次在 R2 点击“通过”。第一票后保持 IN_REVIEW；第二票后 R2 和内容同时 APPROVED。
7Diana · 管理员切换 Diana，打开首条最新请求，对比 R1/R2 快照并导出审计；再打开“用户与权限”。可查看两轮完整历史和成员角色，但仅凭 ADMIN 不出现审核按钮。
账号说明：Alice、Bob、Chen、Diana 是预置账号；`Eva Ramp-up` 等名称是验收过程中创建的自定义 Demo 账号，界面会明确标记“自定义账号”。

05 / Operational acceptance

运行验收

  • 线上 HTTPS 入口返回 200，不要求额外密码。
  • 应用只监听服务器回环地址，由 Caddy 统一代理。
  • 用户级 systemd 服务处于 active、enabled，异常退出自动重启。
  • PostgreSQL 16 由独立服务管理；每次 migration 前自动生成权限为 600 的 pg_dump。
  • 56 条固定 demo 数据可查询，其中 19 条处于开放审核；状态和风险分布符合数据契约。
  • 1280、1440 和 1600 PC 视口无页面级横向溢出，浏览器控制台无错误。
