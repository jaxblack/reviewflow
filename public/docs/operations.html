02 / Filesystem

发布目录

/home/ubuntu/apps/reviewflow/
├── current -> releases/<release-id>
├── releases/
│   ├── 20260917-a7b2181/
│   └── ...
└── shared/
    ├── data/reviewflow.db
    ├── backups/
    └── reviewflow.env
  • releases 保存不可变应用版本，构建通过后才允许切换。
  • current 使用临时软链和原子 rename 切换。
  • shared/data 独立持久化，不随代码发布替换。
  • reviewflow.env 权限为 600，不进入代码库。

03 / Release

发布门禁与切换

  1. 确认本地 main 与 GitHub 同步、工作区干净。
  2. 执行 npm run check，确保 lint、测试和生产构建通过。
  3. 上传到新的 release 目录，排除 .git、node_modules、构建产物、本地数据库和环境文件。
  4. 在服务器 Node 22 环境再次执行 npm ci 与 npm run check。
  5. 停止服务、备份数据库、原子切换 current、重新启动。
  6. 使用有限重试等待健康接口，随后验证公网 HTML、API 和静态资源。
systemctl --user status reviewflow --no-pager
curl --fail http://127.0.0.1:3000/api/health
curl --fail https://qlili.com/reviewflow/api/health

05 / Data

数据、种子与备份

演示数据

种子脚本使用固定 demo-* ID 和 INSERT OR IGNORE，重复执行不会覆盖访问者已经修改的内容，也不会产生重复记录。

npm run build
DATA_DIR=/path/to/shared/data npm run seed:demo

备份原则

  • 发布前停止应用，再复制 db、wal 和 shm 文件，避免不一致副本。
  • 备份目录使用 UTC 时间戳并保留原文件权限。
  • 恢复前先保留当前数据库副本，再切换备份并启动服务。
  • 长期运行应增加定时备份、保留周期和恢复演练。

06 / Recovery

回滚与排障

现象检查处理
健康接口失败用户服务状态与 journal回滚 current 到上一 release 并重启
页面 404Caddy handle_path 与 Vite base确认资源路径以 /reviewflow/assets 开头
写入被锁是否启动多个实例保持单实例，检查未退出进程
会话无法切换Cookie Secure、Path 和签名密钥核对 HTTPS 与环境配置，不输出密钥
演示数据被改动demo-* 数量与历史从备份恢复或清理固定 ID 后重新播种
